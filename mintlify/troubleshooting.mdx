## Health and status

Use `deepclean doctor --json` when checking whether Deepclean is ready to run in a repository. It reports package version, state initialization, config validity, missing state directories, git availability, dirty worktree state, provider availability, privacy settings, and detected project surfaces.

Use `deepclean status --json` when checking what Deepclean already knows about a repository. It is read-only and reports the latest run/report, open queue, blocked items, stale artifacts, recent progress, latest artifact paths, locks, pending revalidation, recommended next command, and git dirty state.

## Common diagnostic codes

- `config_missing`: run `deepclean init` when the repository should use Deepclean state.
- `config_invalid`: inspect `.deepclean/config.json` before running scans.
- `state_dirs_missing`: run `deepclean init` to recreate the directory skeleton.
- `provider_unavailable`: provider-backed synthesis is configured but the provider command could not run.
- `lock_contention`: another write command owns `.deepclean/locks/state-writer.json`.
- `stale_lock`: run `deepclean unlock --stale` before the next write command.
- `malformed_provider_output`: inspect the synthesis attempt ledger, then rerun with a narrower scope or evidence-only mode.
- `privacy_refused`: use `--evidence-only`, `--offline`, `--local-only`, or metadata-only synthesis.
- `verification_failed`: treat the candidate as still open until fixed and revalidated.
- `review_pr_diff_unresolved`: the PR diff could not be resolved from the requested base/head refs.
- `review_pr_target_not_found`: `review-pr --target` did not match an opportunity, candidate, or finding.
- `fix_target_needs_split`: run `deepclean split <candidate-id>` and target one child candidate.
- `candidate_not_fixable` or `opportunity_not_fixable`: use `plan` or `handoff`, or make the required design decision first.
- `verification_required`: add at least one `--verification` command before applying a guarded fix or opening a PR.

## Writer locks

Deepclean serializes state-writing commands so concurrent runs cannot interleave writes under `.deepclean/`.

```bash
deepclean scan --wait-lock --lock-timeout-ms 30000 --json
deepclean unlock --stale --json
```

Active locks are never removed by `unlock --stale`; only stale records are deleted.

## Stale work

When `status` reports stale reports, plans, handoffs, revalidations, or fix attempts, regenerate the named artifact before assigning implementation work.

```bash
deepclean status --json
deepclean report
deepclean revalidate all
deepclean plan <candidate-id>
deepclean handoff <candidate-id> --format codex
```

Stale proof is not proof.
