# Deepclean Vs Other Tools

Deepclean is a local cleanup control plane for AI-shaped maintainability work. It helps developers and agents decide what cleanup PR to do next, what evidence supports it, and what proof is required before calling it done.

It is not a replacement for scanners, test frameworks, hosted PR reviewers, or coding agents.

## Comparison

| Tool type | What it is good at | Where Deepclean fits |
| --- | --- | --- |
| Semgrep | Pattern-based security and code checks | Deepclean can ingest SARIF/Semgrep evidence and turn it into cleanup context. |
| CodeQL | Deep semantic security analysis | Deepclean does not replace CodeQL; it can use findings as part of maintainability planning. |
| Sonar-style platforms | Broad code quality dashboards and governance | Deepclean is local, source-safe, and PR-opportunity focused rather than dashboard-first. |
| OctoCheck | GitHub PR orchestration and comment publishing | Deepclean supplies local PR context; OctoCheck owns publishing and CI orchestration. |
| Codex or Claude Code | Code implementation and agent execution | Deepclean tells agents what to work on, where to stop, and what proof is required. |
| Generic AI refactor prompts | Broad source rewriting | Deepclean rejects broad cleanup as a default and prefers bounded PR-shaped targets. |

## Why not just ask an agent to clean the repo?

Agents are good at making changes, but weak at deciding which messy area should be touched first when the repo is large, stale, or generated by previous agents.

Deepclean gives the agent a constrained target:

- exact candidate or opportunity ID
- files in scope
- supporting evidence
- non-goals and stop lines
- verification commands
- revalidation step

That changes the task from "clean this repo" to "reduce this specific risk with proof."

## Why not just use a scanner?

Scanners find classes of issues. Deepclean organizes cleanup work.

For AI-generated repos, the main problem is often not one lint rule. It is duplicated product decisions, unclear ownership, broad files, missing tests around risky flows, or agent-sized work that needs sequencing.

Deepclean can ingest scanner evidence, but its primary output is a cleanup queue and handoff artifacts.

## Why local-first matters

Deepclean is designed for private repos and agent workstations:

- local evidence is collected before synthesis
- `.deepclean/` state stays in the repository unless exported
- source excerpts are redacted by default
- no-provider modes are available
- source-safe exports omit prompts, payloads, absolute state paths, and generated plan prose

Use Deepclean when the repo needs a trustworthy cleanup map before the next agent or developer starts changing files.
