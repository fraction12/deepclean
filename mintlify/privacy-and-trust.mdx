# Privacy And Trust

Deepclean public alpha is report-first. It does not edit application source code during read-only commands such as `doctor`, `scan`, `status`, `report`, `next`, `show`, `plan`, `handoff`, `revalidate`, `prune --dry-run`, `scrub`, or `export --source-safe`.

## Writes

Deepclean writes state and artifacts under `.deepclean/` in the target repository, including config, run metadata, local evidence, synthesis ledgers, candidates, clusters, reports, plans, handoffs, triage notes, lifecycle events, revalidations, locks, retention manifests, and guarded fix proof records.

Add `.deepclean/` to `.gitignore` unless a repo deliberately wants to share reports.

## Local evidence

`deepclean scan` reads source files and repository metadata locally. It records structured evidence such as file metrics, duplicate windows, import graph summaries, TypeScript and Python structure, git churn, and test-discovery signals.

## Codex synthesis

`deepclean scan` invokes the local `codex` command in read-only mode by default after local evidence collection. By default, the prompt includes structured evidence and redacts source samples.

Use `--allow-source-in-model` only when the target repo and configured provider are allowed to receive source excerpts. Provider execution is disabled by `--evidence-only`, `--offline`, or `--local-only`.

## Source-safe exports

Treat `.deepclean/` as private by default. Use `deepclean scrub --json` or `deepclean export --source-safe --json` before producing a support artifact.
